# KINO Studio 報價工具

公開網站：<https://aaronkino.github.io/qt/>

這是可直接部署到 GitHub Pages 的靜態報價工具，不需要 npm。

## 報價模式

- 快速報價：輸出摘要、條款、付款條件與簽署欄的單頁報價。
- 詳細報價：第一頁沿用快速報價格式，後續頁面列出服務細項。

### 詳細報價預設細項

- 前期：包含「製片統籌與專案管理（行政庶務及後勤費用）」。
- 器材：包含「專業空拍無人機租賃（Hasselblad 6K 或 同級）」。
- 舊版草稿第一次載入時會升級一次並補入這兩個零元預設細項；升級完成後仍可自行刪除。

## 使用方式

1. 填寫報價單號、日期、有效期限與專案概況。
2. 選擇快速報價或詳細報價。
3. 視需要套用付款比例，或開啟「選擇條款」依分類勾選條款。
4. 使用「列印／另存 PDF」，在瀏覽器列印視窗選擇儲存為 PDF。

草稿會持續儲存在目前瀏覽器的 `localStorage`。完整專案、條款範本、條款分類與單條條款可透過 Google 登入同步至 KINO 專用 Cloudflare D1。舊版同步金鑰仍保留為相容模式，但新使用者建議直接使用 Google 登入。

手機按「另存 JSON」時，支援 Web Share 的瀏覽器會開啟系統分享面板，可直接選擇「檔案」、Google Drive 或 OneDrive App 儲存；若裝置不支援，則改為一般 JSON 下載。檔名會優先使用報價單號。

## 簽署印章

簽署區保留原本的手寫簽名，並另外提供「上傳印章」與「調整印章」：

- 可保存多顆印章、命名、選擇、移除，以及用「更換印章圖樣」建立新的印章資產。
- 大章、小章、發票章只是尺寸建議；實際寬度與高度可自行輸入，資料以 `widthMm`、`heightMm` 保存。
- 預設鎖定比例，並可設定 X/Y 正負位移、旋轉、90–100% 透明度、一般／Multiply、置頂／置底，以及是否允許跨出簽署格。
- 「允許跨出簽署格」和「圖層」是兩個獨立設定。未允許跨格時，旋轉後的 bounding box 會納入計算，過大的印章會先縮小以留在簽署格內。
- 透明邊界裁切預設關閉；開啟後只保存 alpha bounding box，不破壞原始圖片。預覽拖曳使用螢幕像素，但最後轉換成 mm 才寫入報價資料。
- 印章在 HTML／列印頁是簽章格上的獨立 absolute layer，沒有把整份報價單 Canvas 化；原有文字仍可在 PDF 中選取、複製與搜尋，也不會把印章推開表格或增加列高。
- 列印前會等待字型與印章圖片載入；若印章圖片尚未可用，會阻止輸出，避免產生缺章的正式文件。瀏覽器列印請選擇 A4、Actual Size／100%，不要使用 Fit to Page。

印章圖片先保留在目前瀏覽器的本機資產清單；登入並在同步差異視窗勾選後，圖片才會上傳至專用的私有 Cloudflare R2 bucket。D1 只保存資產 metadata、版本與私有 object key，報價單則保存當次使用的資產版本與位置設定。後續更換或刪除資產不會改寫歷史報價快照；R2 圖片也不會產生永久公開 URL。

印章 API 與資料表位於 `cloud-sync/`：`cloud_stamp_assets` 管理資產、`cloud_stamp_asset_versions` 保存不可變圖片版本，`cloud_workspace_versions` 會把目前印章 metadata 一起納入工作區快照。對應 migration 是 `cloud-sync/migrations/0006_stamp_assets.sql`。

導覽列的按鈕採統一字級與高度。電腦版會把檔案／模式及專案／雲端分成兩列，手機版預設收合；兩種版面皆可按「收合／工具」切換，以保留主要編輯空間。

## 資料庫管理

電腦版與手機版上方都有「資料庫管理」入口：

- 專案：以目前報價內容新增專案、載入、改名與刪除。
- 條款選擇 POP：分為「選取條款」與「管理資料庫」兩種模式，可依分類篩選、勾選匯入，並直接新增、修改或刪除分類及單條條款。
- 分類管理：分類名稱可新增、重新命名與刪除；刪除分類時，該分類內的條款也會一併標記為「待確認同步」。
- 條款資料庫：每條條款可設定分類與「基本／一般／嚴格」程度，並可個別新增、修改或刪除。
- 「完整專案」保存客戶資料、金額、服務細項、付款、已選條款與簽署設定；「條款資料庫」只保存可跨專案重複選用的單條合約文字。
- 原始六條以固定核心序號保存；POP 的「原始預設」頁籤永遠依原始第 1–6 條顯示，不會被分類排序打亂。
- 「智慧財產權」與「檔案保存」分類依嚴謹程度排列；從 POP 勾選匯入時會略過目前報價中完全相同的文字。
- 未連線時仍可在本機操作；新增、修改與刪除都先保存於本機並標記為「待確認同步」，不會在背景直接改寫 D1。

## 雲端資料庫

- D1：`kino-quotation-data`
- Worker：`kino-quotation-data-api`
- API：<https://kino-quotation-data-api.film-kinostudio.workers.dev>
- 程式與 migration：`cloud-sync/`

登入或按下同步時，系統只先讀取 D1 並顯示「同步前差異確認」，逐類比較本機與雲端的完整專案、條款範本、分類及條款。畫面會進一步列出每一筆「僅本機新增／本機與雲端內容不同」的細項，預設不勾選；使用者可逐筆勾選、全選或清除，再按「合併已勾選項目」。未勾選的本機差異會保留在目前瀏覽器，不會被雲端內容覆寫；僅雲端項目也會保留。使用者仍可選擇「僅載入雲端」，刪除雲端資料則另設預設不勾選的確認項目。只有明確合併或刪除確認會寫入 D1，而且寫入前一定先建立工作區版本。

D1 版本紀錄保存每次同步或還原前的完整工作區快照，可在登入視窗的「版本紀錄」下載 JSON 或還原。清理規則為保留一年，且即使超過一年仍至少保留最新 30 版；執行還原前也會再保存當下版本，避免還原操作本身無法撤回。

Google 登入使用專用 Google Cloud 專案 `kino-quotation` 與 OAuth Web Client。前端只包含可公開的 Client ID；Google 回傳的 ID token 由 Worker 以 Google 公開金鑰驗證簽章、簽發者、受眾與期限，D1 以 Google 帳號的固定 `sub` 建立獨立工作區。登入後由 Worker 簽發 30 天的隨機工作階段權杖，前端只保留於目前分頁的 `sessionStorage`。

第一次使用可由前端以 Web Crypto 產生高強度同步金鑰；API 只使用金鑰的 SHA-256 雜湊分隔資料空間，不保存明文。請將金鑰存入密碼管理器，並在其他裝置輸入同一把金鑰。金鑰不得寫入 `index.html`、GitHub 或其他公開檔案。

## 雲端硬碟規劃

Cloudflare D1 是目前的工作資料庫與跨裝置同步來源。建議將登入、工作資料與專案檔案分工：

- Google 登入：作為手機快速登入方式，不等於必須使用 Google Drive 儲存。
- D1：保存網站中正在編輯的完整專案與條款資料庫，作為跨裝置工作版本。
- OneDrive：維持既有每個客戶／專案資料夾結構，保存定稿 JSON、PDF、試算表與其他製作檔案；電腦端繼續由 OneDrive 同步程式同步。
- Google Drive：如有需要，只做手動備份或分享，不與 OneDrive 同時自動維護同一份 JSON，避免版本衝突。
- Microsoft 登入：採 Microsoft Identity Platform 的 SPA 授權碼流程與 PKCE；前端只包含可公開的 Application (client) ID，不使用也不保存 Client Secret。

目前已完成 Google 帳號登入與 D1 使用者工作區綁定，也已完成 OneDrive 直接登入、資料夾瀏覽／選取與自動儲存。OneDrive 只要求委派的 `Files.ReadWrite` 權限；選定資料夾後，報價內容變更會延遲約 3 秒，以「報價單號.json」覆寫儲存。也可在 OneDrive 設定視窗關閉自動儲存或手動立即儲存。

OneDrive 登入使用官方 `@azure/msal-browser` 5.17.3 瀏覽器套件；登入快取只存在目前瀏覽器工作階段的 `sessionStorage`。本機只記錄選定的資料夾識別資訊與自動儲存偏好，不保存 Microsoft 密碼或存取權杖。Microsoft Entra 應用程式需將正式網站及本機測試網址登錄為 SPA 重新導向 URI，Application (client) ID 由 Worker 的公開設定 API 提供。

## 資料安全

未啟用雲端同步時，報價資料不會離開瀏覽器。啟用同步後，已儲存專案及條款資料庫會傳送至專用 D1；API 僅允許本網站與明列的本機測試來源，並要求有效的 Google 工作階段或舊版同步金鑰。GitHub 公開程式庫不包含 Google Client Secret、Cloudflare API Token、D1 存取憑證或使用者資料。請勿將帳密或其他無關敏感資訊寫入報價內容。
